# AquaShield demonstration scope

Use [the persistent faculty demonstration guide](demo-guide.md) for the current Phase 1–7 scenario, startup flags, generated login credentials, exact URLs, counts, faculty sequence, repeatability and safety checks.

The current `npm run seed:demo` creates a guarded persistent MongoDB demonstration dataset covering reports, accounts, fleet, allocations, trips, genuine non-production demo OTP verification and recorded quantities. It preserves existing records and operator actions on rerun. The old 66-report fixture remains in regression tests and the legacy isolated walkthrough; historical severity/count snapshots from it are not current faculty seed values.

The application remains JavaScript with Gemini and Strands. Severity, confidence, approximate population, fairness and distance/ETA remain backend facts. Four roles pass mocked-success and simulated-provider-failure checks against the faculty data; no live inference was run in this task. Historical authorized results in [the audit](through-phase7-audit.md) are separate: Crisis Detection, Logistics and Early Warning passed, while Resource Allocation returned HTTP 503 and remained unverified. DEMO_AI_MODE simulation and RULE_BASED recovery do not prove live Google execution.

All scenario household conditions, municipal checks, weather, tanker facts and deliveries are simulated, indicated by the environment banner. Unknown inputs stay unknown and population stays approximate. Recorded quantities are not independently measured household receipt; OTP does not establish identity/residency. No silent location collection, new provider, AWS deployment, numeric forecast or Phase 8 work is part of this dataset.

Eventual deployment/video evidence must show actual public URLs, connected health, authorization and persistence after the separate deployment phase is implemented and tested. Local seeds and hosting plans do not prove deployment. Amplify/App Runner compatibility and account eligibility still require checks; MongoDB Atlas can remain the database. Never expose credential files, sessions, private citizen details or API keys in recordings.

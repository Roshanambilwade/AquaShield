## Acceptance blockers and recommended order

No failing application regression was reproduced within the tested local Phase 1–12 contracts. The following are exact unmet acceptance conditions/dependencies, with different scope:

1. **Resolve the simulation acceptance story before development.** A citizen notification inbox and manual officer report verification do not currently exist. If the planned walkthrough requires these, it cannot pass using the existing `/alerts` page or read-only review screen. Define them as separately authorized work, or explicitly retain public aggregates/PENDING reports and omit those claims. Manual verification is already deferred in the specification; it is not silently implemented by seed verification or AI advice.
2. **Address faculty demonstration freshness through authorized observations, without reset/reseed or forced approvals.** Currently zero tankers are eligible. Confirm an available tanker's actual simulated state/operator/water and record fresh observations through existing municipal forms before demonstrating a new recommendation. Keep existing trips/balances/records. This is a data-readiness condition, not permission for the audit to edit them.
3. **Define supported prediction evidence honestly.** All current faculty areas lack required historical coverage. Demonstrate INSUFFICIENT_DATA, or separately authorize an additional labeled history fixture/environment that meets the unchanged quality gates. Do not rewrite old timestamps, lower thresholds or fabricate accuracy. An active current shortage alone does not satisfy forecast history.
4. **Reconcile documentation/status drift in a later authorized documentation task.** README headline still says Phases 1–11 despite its completed Phase 12 section; specification section 74 retains a Phase 9 stop instruction and omits Phase 11/12 from its phase list. Phase 9 says API_PROXY_TARGET does not configure preview, but current Vite config uses that proxy in both dev and preview. Sections describing earlier phase snapshots and the static demo clock need clear historical labels. No document was silently rewritten in this audit.
5. **Before claiming real four-role AI acceptance, obtain separate authorization and run the existing bounded diagnostic commands.** Current live availability for every role is unverified, and the historical Allocation 503 is not a pass. This is not a blocker for offline deterministic simulation/numerical operations.
6. **Before public deployment, complete the separate infrastructure gates:** restore Docker engine and rebuild/run current images, then approved backup restoration, authenticated/TLS Mongo/index/ACL checks, trusted proxy/security/secret review, image/advisory scans, capacity/multi-instance checks, cloud compatibility and public URL/auth/report/restart acceptance. Do not treat local verification as AWS deployment proof.

An isolated simulation using only currently supported local workflows can be designed without live Gemini or AWS. A simulation promising personalized citizen alerts, manual verified reports or supported forecasts on the existing faculty history remains **not accepted as that complete story** until the corresponding scope/evidence gaps are addressed. No confirmation, new feature or automatic follow-on phase is implied by this report.
